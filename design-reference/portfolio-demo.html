The system on show

business-mono — a solo-built multi-agent operations platform

A hub-and-spoke architecture: a coordinator agent (Simon) routes work to a roster of specialists, all sharing one Supabase database. A Mastra server runs the agents and workflows; a Next.js app handles dashboards and approvals. Below is the shape, then the decisions worth talking about.

Directors (Signal · Web) ↕ Simon — coordinator (only agent that talks to humans) ↕ Recorder · Archivist · PM · BA · Content · Researcher · RM · Marketer · Compliance ↕ Supabase — Postgres + pgvector (shared)
Retrieval

Hybrid search, not just vectors

The knowledge base combines pgvector (HNSW) similarity, graph traversal over knowledge connections, and Postgres full-text — so lookups use the right method for the question.

Control flow

Suspend / resume elicitation

The requirements agent runs multi-round clarification loops, pausing mid-workflow for human input and resuming — structured elicitation, not a single prompt.

Safety

Approval graduation

Actions move human-confirmed → batch → autonomous as they earn trust. Emails, published content, and CRM writes stay human-approved regardless of track record.

Governance

A compliance gate in the loop

A dedicated compliance agent reviews advice-framed drafts against AFSL rules, logs verdicts, and never auto-approves — re-running when copy changes.
